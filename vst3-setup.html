MYGRAIN VST3 for Mac / Bitwig Studio

Separate Bridge instrument and FX stereo effect. Universal binaries: native Apple Silicon (ARM64) + Intel (x86_64), macOS 11 or newer. Rosetta is not required on Apple Silicon. Google Chrome runs on the same Mac.

Mac · MYGRAIN Bridge 0.8.0 Mac · MYGRAIN FX 0.4.0

  1. Download and extract each ZIP you want. Close Bitwig Studio.
  2. Open Terminal and enter the extracted folder: type cd with a trailing space, drag the extracted folder into Terminal, then press Return. Run:
    ./"Install MYGRAIN.command"
    Use the capital I in Install. The ./ means the current folder; the quotes keep the filename’s space together. Keep the installer, plugin bundle and SHA256SUMS.txt together in this folder.
  3. If Terminal reports Permission denied, run bash "./Install MYGRAIN.command" from the same folder instead. The installer verifies hashes/signatures, installs the whole bundle into ~/Library/Audio/Plug-Ins/VST3, and backs up an existing version outside the scan folder. No administrator password or extra audio driver is needed. It removes quarantine only from the installed plugin, without changing global Mac security settings. These previews are ad-hoc signed, not Developer ID signed or notarized.
  4. Open Bitwig → Settings → Locations → Plug-in Locations. Add ~/Library/Audio/Plug-Ins/VST3 if it is missing, then rescan VST3.
  5. Add MYGRAIN Bridge as an instrument on an instrument track, or MYGRAIN FX as an audio effect after the sound you want to process. They can be installed alongside each other.
  6. Open the plugin window and click Open MYGRAIN in Chrome. Sign in normally, allow local-network access if asked, and press Start MYGRAIN once if Chrome needs an audio gesture. Click green Arm and keep Bitwig track processing/monitoring enabled. Each plugin instance needs its own MYGRAIN tab.

Bridge: choose Live to edit while playing, or Rendered for timeline-positioned snapshot playback. FX: use the DAW INPUT card to choose routing and dry/wet. FX has a fixed 1,000 ms compensated delay; print wet audio in real time. Offline FX output, Stop, bypass and lost returns use aligned dry audio. DAW Play/BPM clocks silent patch sources for modulation.

Manual fallback: Copy code in the plugin, then paste into MYGRAIN’s VST3 panel (Bridge) or DAW INPUT card (FX). To remove a plugin, close Bitwig and remove its bundle from the user VST3 folder.

Mac preview. Universal Mach-O binaries, SDK validation and native-host audio/editor checks run on a macOS build runner. Physical Mac / Bitwig / CoreAudio recording alignment is not yet verified. Store MYGRAIN in project embeds the editable patch and its sounds, plus the retained loop in Rendered mode. Chrome itself is not embedded.

MYGRAIN Bridge for Windows

A portable VST3 instrument with two explicit playback modes: Live for editing while playing, and Rendered for immediate DAW timeline playback. Chrome runs on the same PC.

Download Windows x64 ZIP · preview 0.8.0

Preview release. Automated verification is described in the ZIP. Real Windows DAW compatibility, audio-driver behaviour and recording alignment still need testing. This is not a fully native MYGRAIN instrument.

MYGRAIN FX — stereo DAW input / effect return

Download MYGRAIN FX Windows x64 ZIP · preview 0.4.0

Separate from the Bridge instrument, with the same modern native interface, green Arm, red Stop, orange Play and stereo input/output meters. Install MYGRAIN FX as a stereo insert effect on an audio track, instrument output or send bus. DAW audio goes into Chrome’s separate DAW INPUT card, through the selected MYGRAIN effects, then back to that same plugin. Do not send its return back into its input.

  1. Extract the FX ZIP. Close the DAW, copy the whole MYGRAIN FX.vst3 folder into C:\Program Files\Common Files\VST3\, then re-scan. Keep MYGRAIN Bridge alongside it; the identities are different.
  2. Add MYGRAIN FX as an effect, open its window and click Open MYGRAIN in Chrome. Sign in normally; it connects automatically. Allow local-network access and press Start MYGRAIN once if Chrome requires an audio gesture. Manual fallback: copy the FX code into the new DAW Input card and click Connect FX.
  3. Enable monitoring/processing on the DAW track. Press green Arm. FX runs whenever the DAW processes the track, including while transport is stopped. Orange Play also enables the effect. The incoming audio still works while transport is stopped; DAW Play runs silent patch sources for modulation. Host BPM clocks those sources and Filter Playground; if musical timing is unavailable the patch BPM is used. This browser scheduling is buffered, not sample-accurate DAW-grid phase lock.
  4. Choose the input route: Filters + main/final effects, main chain after the input filters, Turntable / R / Wasp final stage, or Direct return for an unprocessed transport check. Existing effect enable/bypass and placement controls still apply. Use R source All to excite it from DAW input.
  5. The card has input gain, stereo input meters, input mute and aligned dry/wet. Arm is effects-only: the patch’s enabled layers run silently for modulation, without changing their levels, On/Off or solo settings. Wasp routes temporarily process the DAW input using their existing patch sources. R uses source All; individual layer excitation is excluded while armed. Stop/dry or Disconnect restores normal layer routing and any previously running transport. Host Stop, bypass and processing interruptions retain the armed layer mute. Input Mute affects DAW input only; existing effect tails can continue. At less than 100% wet, the native dry component is unaffected by input gain/mute.
  6. Fixed one-second transport delay: the plugin reports 48,000 samples at 48 kHz, 44,100 at 44.1 kHz, and the equivalent at other supported rates. Sample-indexed returns are presented exactly one second after their source sample. The DAW can compensate playback using this value; it cannot remove live-monitoring delay. Effects’ own musical delays/tails remain part of the sound. This is a creative send/return, not low-latency live guitar monitoring.
  7. Stop, native DAW bypass, missing/late return, disconnect and offline processing use the same one-second delayed dry signal. No sudden undelayed fallback. An initial one-second fill is silent. Arm remains latched across routing/lifecycle interruptions and reconnects; only explicit Stop/disarm clears it. The DAW project saves Arm, bypass and dry/wet; Store MYGRAIN in project also captures the editable patch, required sounds and browser input gain/routing. Wait for Ready for DAW save, then save your DAW project.
  8. Use real-time recording/export to include Chrome effects. Offline bounce/freeze returns delayed dry only and the card/native editor says so. There is no cached FX snapshot or automatic fallback render. Record/print the wet return before using offline export. FX is stereo, 32/64-bit processing, 8–192 kHz; no sidechain, MIDI, multichannel or native effect automation except standard bypass.
  9. One FX instance per Chrome tab. Instrument Bridge and FX cannot own the same tab; use separate tabs and separate plugin instances if needed. Each uses a private, per-instance loopback connection. Chrome’s direct monitor is muted while connected. Closing the plugin editor leaves processing connected.
  10. Saved Songs/WAV: DAW live input and its session routing are not saved in patch ZIPs or server Song renders. They do not silently become a live dependency of a saved Song. To use this material in a Song, print the FX return to an audio file and import that audio through the normal sample workflow. Existing saved parts/caches are unchanged.

This is a preview. See VERIFICATION.txt in the ZIP for actual automated native-DLL/Chrome checks. Wine/custom-host testing is not physical Windows/ASIO/commercial-DAW validation. Confirm compensated recording alignment in your DAW.

Bridge instrument: copy, then re-scan

  1. Use a 64-bit VST3-capable Windows 10/11 DAW. This build is x86-64, not 32-bit or native Windows ARM. Chrome must be installed.
  2. Download the ZIP and choose Extract All. Inside it is a folder named MYGRAIN Bridge.vst3.
  3. Copy that whole folder to C:\Program Files\Common Files\VST3\. Accept the Windows permission prompt if needed. The result should be C:\Program Files\Common Files\VST3\MYGRAIN Bridge.vst3\Contents\x86_64-win\MYGRAIN Bridge.vst3. Do not copy just the inner binary or the ZIP.
  4. Alternatively, the standard current-user location is %LOCALAPPDATA%\Programs\Common\VST3\. Some DAWs may need that path added to their scan locations. The Program Files location is the simplest first choice.
  5. Open the DAW and re-scan VST3 plugins (or restart it). Add MYGRAIN Bridge as an instrument, not as an audio effect.

Updating an earlier version: close the DAW completely, replace the existing whole MYGRAIN Bridge.vst3 folder with the new one, then re-scan. Reload MYGRAIN in Chrome. The plugin identity is unchanged; no installer is needed.

Connect Chrome

  1. Open the plugin window and click Open MYGRAIN in Chrome. This enables a listener on 127.0.0.1 only; nothing is installed as a background service.
  2. Chrome opens MYGRAIN with the code filled in and connects automatically. Sign in normally if asked. Allow Chrome’s local-network permission if prompted. MYGRAIN starts automatically when Chrome permits; if audio is blocked, press Start MYGRAIN once. No separate Connect click is needed.
  3. Load or create a patch. Use the plugin’s green ▶ Arm to follow the DAW, red ■ Stop to stop and disarm, and orange ▶ Play to audition while the DAW is stopped. Arm can be selected before connecting. Play becomes available once Chrome audio is ready; Stop can always clear a latched Arm. When the DAW is already playing, Play schedules a future live start.
  4. Manual connection is still available: choose Copy code / manual connection in the plugin, open MYGRAIN in Chrome, press Start MYGRAIN, expand Windows VST3, paste the code and click Connect. Each plugin instance has its own code.
  5. Choose Playback mode → Live to change sounds, samples and effects while the DAW plays. No render or refresh is needed. Click Arm · follow DAW, then Play. The first live start is scheduled at a future bar (at least one second ahead); subsequent edits arrive after roughly 350 ms of buffering.
  6. Live keeps playing through DAW loops and seeks, even when the host supplies no cycle metadata. It does not stop to schedule a new start. MYGRAIN advances as a continuous performance: rewinding the DAW does not rewind MYGRAIN’s pattern. This is the live-looping workaround; it does not repeat the same captured audio section at every DAW loop.
  7. For playback from timeline zero and repeatable timeline-positioned loops, choose Playback mode → Rendered and stop the DAW. Select a rendered loop length, then click Render / refresh loop. Preparation first plays one warm-up cycle, then captures the next cycle on exact sample boundaries. This keeps the startup fade out of the repeated loop: four bars at 120 BPM takes about sixteen seconds, plus setup. No blanket fade or extra EQ is applied.
  8. When ready, click Arm · follow DAW if not already armed, then Play. Rendering retains your Arm choice; it never overrides a Stop. The plugin reads rendered audio from the DAW’s current musical position, including the first callback at timeline zero. Loop wraps and seeks do not wait for Chrome or schedule a future bar.
  9. Rendered is a snapshot. Patch edits are not heard until you stop the DAW and click Render / refresh loop again. Switching Live → Rendered reuses the last successful render without capturing it again; if already armed, it can play immediately at the DAW position. It may differ from your current live edits. Arm stays latched across mode changes. If already armed and the DAW is playing, selecting a mode can start it: choose Stop first if you want silence while switching.
  10. Do not edit the patch while a render is being captured. Length choices are 4/4 bars (four quarter-note beats each), independent of the host’s meter; Rendered follows host quarter-note position. Maximum rendered audio is 32 MiB stereo float32; choose fewer bars if needed. Store MYGRAIN in project in Rendered mode embeds the retained loop along with the editable patch; then save the DAW project.
  11. Start now / next bar auditions the rendered loop while stopped, or schedules a live start. The DAW must process the instrument: enable track monitoring if needed. Hosts that suspend stopped instruments cannot output an audition until processing resumes.
  12. Chrome’s direct speaker route is muted while connected; listen through the DAW. Stop / disarm silences the plugin. Disconnect also stops the browser patch and restores normal Chrome monitoring. Closing only the plugin editor does not disconnect.

Randomise, mute layers and cook effects from the plugin

The Cooking pot sits beside Layers in both plugins, using the same effect icons, colours, linked power switches, draggable order, arrow controls, Stir and BIG STIR as Chrome. Click an effect name to jump to its browser card. Bubble Chamber remains manual-only. Pot order and powers are part of the editable patch. Mega keeps DAW tempo and never asks its tempo question while a plugin is connected.

Sparse Random and Mega Random use the same generators as MYGRAIN in Chrome and replace the current patch. Undo remains available in MYGRAIN. The native status box shows actual completed layer jobs, current work and warnings. There is no invented percentage while the initial patch is being chosen.

The 25 Layers switches mirror the browser’s Quick Mutes, including global reverb/delay. Lit = On; dark = muted. Solo settings still apply. FX layers remain silent modulation sources while FX is armed. Chrome must be connected, signed in and audio-ready; controls are disabled during generation, recording, recall and other conflicting operations.

In Live mode layer edits are heard through the existing buffered stream. In Rendered mode the retained audio does not change until Refresh render; stop the DAW first. Use native Store in project afterwards, wait for Ready for DAW save, then save the DAW project. Stop/disarm remains available throughout.

Store and recall with a DAW project

  1. Keep the plugin’s own Chrome tab connected. Auto-store is On by default, checking every 60 seconds; choose 15–3600 seconds or pause it in either interface.
  2. For updated Rendered audio, render / refresh the loop first.
  3. Wait for a completed Auto-store or press Store now in Bridge or DAW Input.
  4. Wait for Ready for DAW save, then save the DAW project normally.

Both interfaces show the last completed store time, duration, transferred bytes, snapshot size, store/unchanged counts, total transferred and next check. Payload figures include project headers, not TCP/WebSocket framing. Unchanged samples are reused; unchanged patches transfer nothing. Playback continues; recording/loading/edit operations defer automatic stores. If DAW Save happens mid-transfer it contains the previous completed snapshot. Rendered audio still needs an explicit refresh.

Store alone does not write your DAW project to disk. Auto-store includes later edits at the chosen interval; save the DAW project normally. It captures the current patch and required samples/recordings, not the Songs library, account credentials or connection codes. Maximum patch: 128 MB plus at most 32 MB Rendered PCM.

On reopening, use Open MYGRAIN from the plugin. Its dedicated tab restores the saved patch before enabling audio. Sign in normally and press Start MYGRAIN once if Chrome needs an audio gesture. Restore project snapshot retries a failed recall or reloads the stored version. Each plugin has its own snapshot and tab; recall does not overwrite the account’s remembered scratch patch/audio.

Stored Bridge Rendered audio plays natively without Chrome, including offline output. Live Bridge and FX wet processing still need Chrome. FX gain, mute and input route are recalled with the editable patch; Arm, native bypass and dry/wet are saved by the DAW. Existing older project states remain readable.

Recording and saving

  • Arm stays latched when adding/routing tracks, when the host rebuilds its audio graph, and through temporary processing/connection loss. Audio is silent while unavailable. When processing returns, Rendered follows the timeline; Live schedules a new future-bar start. Stopped manual audition needs Play again after a processing rebuild. Only Stop / disarm clears Arm. Disconnect retains Arm for reconnection. A stored Rendered loop can continue following DAW playback without Chrome; use Stop / disarm to silence it. Arm is stored by the DAW; use Store MYGRAIN in project to embed the patch and optional loop.
    Route or record the instrument output using your DAW’s normal method. Some DAWs require another audio track to record a plugin instrument. Live streaming requires real-time recording or real-time export.
  • Live stream: faster-than-real-time bounce/freeze is silent. Rendered loop: cached audio can be processed in offline mode without waiting for browser audio. Keep the plugin armed. A stored Rendered loop needs no Chrome connection. Actual commercial-DAW offline export still needs testing.
  • Wait for a completed automatic store (or press Store now in Chrome), then save your DAW project. This embeds the current editable patch and required sounds, plus the retained loop in Rendered mode. Auto-store includes later edits; save the DAW project normally. On reopening, connect Chrome from that plugin to recall automatically; no manual patch loading or re-render is required.
  • This first version streams the live editor’s final mix, including its effects. Frozen Song playback and independent repository/media previews are not bridged. Stop them before connecting.
  • Rendered playback is indexed by DAW musical position; live playback selects a future start. A Windows-DLL test host verifies first-callback playback and exact rendered samples across repeated cycles. Actual commercial-DAW recording alignment must still be measured in your setup.

What to expect

  • Only one browser connection can control each plugin. A second tab is blocked before starting audio; other profiles/browsers are also refused while a connection is active. Open Chrome is disabled in the plugin while connected. Disconnect the owning tab (or use the plugin’s Disconnect) before connecting another. Separate plugin instances can each have their own tab. Manual connection remains available.
  • Preparing a loop and starting a live stream require a whole-number tempo from 1–300 BPM. Rendered playback follows tempo and musical position supplied by the DAW; tempo changes change playback speed/pitch (no time-stretch). Missing musical timing leaves rendered playback silent with a status message.
  • Live mode: DAW stop stops the browser patch. DAW loops and seeks keep streaming, regardless of cycle metadata. Tempo/meter changes and actual buffer starvation still re-arm on a future bar, which can cause a gap. Continuous live tempo ramps remain unsupported. Rendered mode: stop, seek, resume and cycling read cached audio at the new DAW position without re-arming. The render no longer captures the initial transport fade-in. Arbitrary DAW cut points, non-repeating synthesis and evolving/random effects can still have different endpoints; there is no added pause, blanket fade or crossfade.
  • Live mode resamples browser audio and makes bounded drift correction. Rendered mode interpolates the cached audio at host timeline position; it does not generate MYGRAIN synthesis natively.
  • Bridge has no DAW parameter automation, MIDI-note forwarding or plugin audio input. Explicitly stored snapshots recall automatically when their plugin reconnects.
  • Keep Chrome running and prevent the MYGRAIN tab from being discarded. Normal Chrome local-network permission is supported; do not disable browser security or expose the bridge port to your LAN.

If there is no sound

  1. Check that the plugin was scanned as a 64-bit VST3 instrument and its track is enabled and monitored.
  2. Check that MYGRAIN has started, an audible patch is loaded and the panel says Connected. For immediate timeline playback, check that a rendered loop is ready and armed.
  3. Try playing the DAW, then click Arm again. Some hosts suspend instrument processing while stopped.
  4. If Connect fails, copy a fresh code from the current plugin instance and check Chrome’s local-network permission. Close any previous tab connected to that instance.
  5. Watch the buffer and underrun status. If underruns rise, reduce MYGRAIN/DAW load and reconnect. Different Windows audio-driver combinations may need testing even though audio itself is captured inside MYGRAIN, not from the speaker device.

Remove it

Close the DAW, remove the MYGRAIN Bridge.vst3 folder you copied, and re-scan. There is no installer, Windows service, registry registration or helper application to uninstall.
