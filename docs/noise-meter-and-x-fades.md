# Noise meter and Loop X sample ends

**Noise implementation superseded by NOISE-N.1:** see [noise-n.md](noise-n.md).
N now generates independently; the mixer meter reads its output. The audio
regression below retains the historical granular fallback fixture; the live-meter
regression follows N. The historical details below are not the current N design.

Release: `v2026.10.25.NOISE-AUDIO.1` (2026-10-25).

## Noise

The mixer Noise control mirrors `noiseMix` across its existing full 0–100%
range, including saved state. This is a noise/sample blend, not a post-master
loudness control. Default levels and randomisation limits are unchanged.

Noise is generated by `playGrain`, not the oscillator engine. Its mixer VU now
uses `granularNoiseMeterGain`, fed by a noise-only branch. Each voice mirrors
its output gain/keyboard decay; the bus mirrors granular enable/trim/solo gain.
It has no audible return and cannot double the noise signal. Custom grain
output destinations (for example Q) are excluded from the main Noise meter.
Per-voice taps disconnect on native source end. Audio graph rebuilds replace
the bus; existing VU tap synchronization replaces its analyser as needed.

## Loop X

**Historical change, subsequently reverted:** the X envelope/tail changes below were rolled back at Mark’s request in `v2026.10.25.X-ENVELOPE-RESTORE.1`. Noise-meter improvements remain. See `x-envelope-rollback.md`.

A short, trimmed or pitched sample can end before the requested step window.
Previously X's minimum step/preview durations could leave its envelope above
zero at the native source end. The sample's remaining duration now bounds the
voice and attack, with a terminal fade to zero. Linear pitch slides account for
sample consumption during and after the ramp. Main scheduling, preview and
key-hold preview use the corrected boundary; synth playback is unchanged.

## Regression checks

Run from the repository root:

```
node tests/noise-meter-audio-browser.cjs
node tests/noise-meter-live-browser.cjs
node tests/x-sample-edges-browser.cjs
```

These fetch the public static app in disposable Chromium/WebKit contexts,
mock account/API reads and block all non-GET/HEAD and off-origin requests.
They never use real account sessions or write production stores. Evidence
JSON goes to `/tmp`, or an existing `MYGRAIN_AUDIO_EVIDENCE` directory.

Noise checks exercise both UI event directions, reload restoration, native
44.1/48 kHz PCM, noise-only isolation, mute, keyboard decay, source cleanup and
bit-identical audible output with/without meter taps. The realtime test checks
the actual terminal analyser and displayed dB. X uses DC samples intentionally:
any cutoff transient is introduced by the envelope, not the sample. Pitch,
slides in both directions, longer slides, playback and previews are covered.
Key-hold edge thresholds allow its intended linear-release slope.

These are native browser audio tests on the server, not physical MacBook tests.
Submitted diagnostics can capture gain/scheduler evidence but do not measure
hardware underruns. Correcting a reproduced sample-edge click does not prove
that every reported MacBook crackle had that cause.

## Follow-up: X note onset (X-CLICK.1, 2026-10-25)

The next submitted Safari report confirmed NOISE-AUDIO.1 had loaded and X was
still clicking in sample mode, with X delay off, filter LFO depth zero and no
reported scheduler skips. Its aggregate diagnostics did not identify the exact
sample, attack, trim, filter mode or pattern; absence of these fields is not
proof of their values.

Native PCM reproduction found an additional, independent onset problem:
X's straight minimum 1ms attack ignored the existing global Click Guard.
It also joined exponential decay at a sharp slope change. The new X-only
sample attack honours Click Guard (bounded to fit short sources), uses a
raised-cosine attack, and eases into its exponential decay. The requested
peak level and terminal decay/end timing remain. Scheduling and preview share
the protection; OSC3, L and other channels are unchanged. User attacks longer
than the guard remain effective. No source files or saved-state schemas change.

`node tests/x-sample-onsets-browser.cjs` runs a native 70Hz-cosine probe through
X's real filter/EQ routing at 44.1/48kHz in Chromium/WebKit. Onset high-frequency
energy is required below -90dB relative to the probe window, with audible
output and complete source cleanup; the previous build measured approximately
-47dB (0ms attack), -62dB (4ms) and -71dB (20ms). This measures generated onset
artefacts, not whether a user's recorded bass sample contains intentional
high-frequency transients. The existing 40-case source-end regression still
passes, including pitch slides and held previews.

Detailed submitted logs now include `application.loopX`: source identity,
root/region/duration, exact relevant controls, pattern, active section and X
EQ settings. Ordinary compact monitor samples remain unchanged. This permits
exact reproduction of a future X report without asking for missing controls.
No browser regression establishes a physical MacBook listening result.
