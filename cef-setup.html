MyGrain CEF

Separate embedded-app VST3 instrument · 0.1.4 preview

The complete hosted MYGRAIN app runs inside the plugin. Normal app updates appear on a new instance or after Store + reload app. No external Chrome window or connection-code copying is required.

Windows x64 · CEF instrument 0.1.4macOS 13+ · CEF instrument 0.1.4 · Apple Silicon + Intel

Existing MYGRAIN Bridge 0.8.0 and FX 0.4.0 are unchanged. This installs alongside them with its own name and plugin ID.

0.1.4: Space controls the DAW while the plugin/app has focus, without toggling the app loop or activating focused app buttons. Text fields still accept spaces. Includes retained sign-in across plugin instances, native filename/confirmation dialogs for WAV Repository and Loop Store exports, and WAV/widget/inline previews routed through the DAW output while stopped/disarmed. Includes the earlier toolbar, auto-save, keyboard and repaint fixes. Close the DAW and replace the entire older CEF bundle, then rescan.

Install

  • Windows: extract the ZIP, close your DAW, then copy the whole MyGrain CEF.vst3 folder into C:\Program Files\Common Files\VST3\. Keep its cef runtime folder intact.
  • Mac: macOS 13 or later. Close your DAW. Extract the ZIP, open Terminal, type cd and drag the extracted folder into Terminal. Press Return, then run ./"Install MyGrain CEF.command". Permission fallback: bash "./Install MyGrain CEF.command". Keep the installer, bundle and checksum file together. Installs only this plugin into your user VST3 directory and backs up an older CEF bundle. Ad-hoc signed, not Apple Developer-ID signed/notarized; no global security settings are changed.
  • Rescan VST3 plugins. Add MyGrain CEF as an instrument and open its editor. Sign in, then press Start MYGRAIN if requested. Arm follows DAW transport; Stop disarms.

Auto-save is retained

On by default · checks every 60 seconds · adjustable from 15 to 3600 seconds.

Use Auto-save: On/Off in the native toolbar. Enter the interval under Every (s) and click Apply. The two info lines show output/DAW state, current store activity, last completed store time and duration, transferred/patch size, completed/unchanged counts and next check. Paused, deferred and failed storage is reported without discarding the last completed snapshot.

The plugin automatically stores the editable patch, required samples and a retained prepared loop. Unchanged patches skip transfer; loads, recording and other busy operations defer it. Store now remains available.

Save your DAW project normally after “Ready for DAW save”. Patch auto-store does not invoke the DAW’s File → Save. A DAW save during a transfer contains the previous completed snapshot; failed stores retain it.

Closing the plugin window leaves the browser engine, audio and automatic storage running. Reopening the window resumes that same instance. A fresh instance restores its saved patch and auto-store settings after signing in/starting audio.

Reload and recall

Store + reload app waits for a successful snapshot, reloads the current hosted app and reconnects/restores the patch. A busy or failed store cancels the reload. Reload interrupts Live audio; stop the DAW first. Closing and reopening the editor does not silently reload or restart playback.

Browser profiles remain private to each instance. Sign in once: the authenticated session is remembered locally across new instances until you log out or the server session expires (normally 90 days). Passwords and session tokens are never embedded in DAW projects. Internet is required for the hosted app and account services. Chromium runtime or bridge-protocol upgrades can still require a new plugin build.

Repository exports and previews

Export Final Mix to Repo and Add to loop store use native filename dialogs. Confirm the name to save, or Cancel to save nothing. WAV Browser playback, decoded loops and other browser/widget auditions feed the plugin’s stereo DAW output even when its main transport is disarmed. Your DAW must keep the track processing; enable monitoring if needed. Preview auditions are excluded from native offline bounce.

Preview boundaries

Live mode retains the existing Bridge buffering/timing behavior and requires real-time playback. Rendered mode retains prepared-loop native/offline playback; refresh the render after sound changes. This does not add DAW automation. Native OS-file drag/drop and international IME are not integrated; use file pickers/click controls. See the included VERIFICATION.txt for the exact tested builds, native-runner checks and remaining physical DAW/device coverage.
