## K keyboard recording (K.1)

Build `v2026.10.21.K.1` changes **Record Keyboard / Rec K** to stop the current pattern, play a four-beat count-in at the current BPM, and restart the current editable pattern on the recording downbeat. An armed Song cache does not replace that pattern. A second Record press cancels without replacing the preceding take; cancellation during the final count-in beat also stops future-scheduled sources. Missed transport deadlines cancel visibly rather than saving an unaccompanied take.

**Set Recording Level · K** and a recording VU are directly below the keyboard. Raised defaults are Grain 160%, Osc 180%, Q Piano and Q Strings 250%; each sound remembers its own 0–400% setting in the existing account-scoped patch/state. Explicit older non-default gain settings migrate; the former default of 100% adopts the new instrument defaults. Recording level is protected from patch randomisation. It scales only the keyboard capture bus, once, before metering/recording; it never changes the monitored instrument, metronome or backing, and no post-capture gain is applied again. The VU shows recording RMS/peak and a clipping warning. Its analyser connection and 10 Hz timer exist only while the meter is intersecting the viewport and the document/audio context is active.

Checks: `node --test tests/k-count-in-level.test.js`; `tests/k-count-in-level-browser.cjs` uses only the disposable loopback server for native touch controls, four real instrument captures, count-in/transport alignment, exact live input gain, backing/count-in exclusion, cancellation, saved settings and portrait/landscape layouts. Installed Linux WebKit lacks MediaRecorder: its real VU/layout/persistence checks run, but actual captures run in Chromium. Physical iPhone recording remains untested. No stored audio or Song/Undo device-ownership formats are changed.

## RadioLab current-take preview and normalization (R.10)

- Current build: `v2026.10.17.R.10`. After **Record → Stop**, use **Preview** in the main RadioLab panel to hear the current unsaved take. The same button stops its preview; finishing playback resets it automatically. Preview does not require saving or opening the recording browser.
- **Normalize** peak-normalizes the stopped take to 0 dBFS, using one gain across both stereo channels to preserve their balance, duration and station metadata. Preview subsequently plays that normalized audio. No compression, tempo processing, looping or stereo-to-mono conversion is applied.
- **Save always writes the normalized take**. If Normalize was skipped, Save applies it first. Normalization is idempotent, failed saves retain the take, and a new successful recording starts with fresh normalization state. Silent/empty or active recordings cannot be previewed, normalized or saved.
- Existing saved recordings, private storage/API formats, relay capacity limits, navigation colours and working station playback remain unchanged. Main-panel and browser previews share one playback lifecycle; normalization stops preview before changing its audio. Physical iPhone behavior still requires device confirmation.

## RadioLab server-decoded recording (R.8 history)

- Build `v2026.10.17.R.8` replaced a recorder that waited indefinitely when native station playback was audible but the browser's Web Audio tap returned silence. Recording now reads decoded PCM directly from the authenticated server, independently of the media element, AudioWorklet, ScriptProcessor, audio-context state and rewind buffer.
- Press **Record**, wait for the recording timer to advance, then **Stop** and **Save**. Capture is manual and live-only; rewind/pre-roll and its audition controls are removed from the visible UI. No microphone permission or automatic recording is involved. A failed or cancelled start preserves the previous take until actual nonzero server PCM arrives.
- The approved relay accepts `_radiolab_format=pcm`, returning stereo signed 16-bit little-endian PCM at 44.1 kHz. The server decodes only bytes from its existing allowlisted, DNS-pinned upstream connection; the decoder receives no network URL. Monitoring and recording have separate scoped connections, so monitor playback can be slightly ahead or behind the recorded live feed. Existing two-per-account/eight-global limits remain enforced. Stop, failure, replacement and page/account teardown release capture and decoder resources.
- Save, preview and complete-file loading into Main Grain, Grain A, Grain B and V retain the existing private sample format and account boundaries. The existing recording limit remains 120 seconds or 32 MiB float PCM, whichever is first (about 95 seconds at stereo 44.1 kHz). Existing saved recordings, Song/patch schemas, navigation colours and working station playback are unchanged.
- `tests/radiolab-server-record-browser.js` reproduces an advancing native player with a deliberately silent browser audio tap, and checks direct recording, save, saved-file signal, preview, all four destinations, failure preservation and retry. Save/load checks are restricted to disposable loopback stores; public verification never saves samples. Linux WebKit coverage is not physical iPhone verification.

Song editing actions, including **Amend**, request editing access automatically;
there is no separate Edit Song step. Another device's lock is still protected.

controls stay in place; copy/paste is an additional option, not a new mode.

if needed without overriding another device's lock. It replaces that saved loop

re-arms automatically, reusing unchanged audio. The copy lasts until reload or a

- Resource captures include active layers/voices/grains, waveform-cache sizes, deduplicated known decoded-buffer PCM size estimates, browser JS heap when exposed, synth waveforms/sync/LFO routes, relevant FX/trim values, a short analyser RMS/peak sample and settings/state of already-open microphone tracks. The diagnostic collector does not request microphone permission, include device/group IDs or microphone labels, record audio, enumerate devices, change audio-session settings or restart the engine. There is no automatic upload; Submit Log explicitly sends diagnostic text and device details, not audio or sample contents.
- Retention is bounded: one timer sample per second, 180 ten-second resource snapshots (about 30 minutes), 80 recent lifecycle/fault events, 120 recent timer-delay samples and five marked incidents. Each incident freezes its current details plus up to twelve preceding timeline points and twenty events. The visible console refreshes at most once per ten-second history update unless copied, marked or explicitly using the live panel (1 Hz); focused text is left alone. Clear Log clears the current in-memory history and current saved checkpoint; monitoring continues. Delete Saved Log deletes only the selected previous local session. Neither action deletes server submissions or affects settings/samples.
- Unsupported readings are explicit. Exact iPhone model, temperature/thermal state, total process/native audio memory, hardware underrun counts and unexposed Bluetooth/output routing are not inferred. PCM estimates exclude unknown caches/native overhead and are not total RAM usage; browser/user-agent hardware hints are not a verified device specification.
- `node --test tests/audio-diagnostics.test.js` exercises missing APIs, interrupted contexts, background transitions, clock stalls, privacy filtering and two simulated hours of bounded retention. `node tests/audio-diagnostics-browser.js` checks phone portrait/landscape views at 44.1/48 kHz, missing-API fallbacks, an injected main-thread stall, Mark/Copy/JSON download, suspension/resume, safe rendering and zero microphone requests. These are Chromium emulation checks, not physical iPhone/Safari verification.

### Local restart recovery

- `audio-debug-storage.js` checkpoints the current report into its own IndexedDB database, `mygrain-audio-debug-v1`, normally every five foreground seconds while an audio context exists. It reuses the existing one-second probe, not another polling timer, and never writes from an audio callback. Fault/lifecycle events request a faster checkpoint (at most once per second); Mark Crackle and manual submission request an immediate save. Visibility/page-hide writes are best-effort extras, not the recovery mechanism.
- Checkpoints use asynchronous transactions and request strict durability when supported, falling back to normal IndexedDB transactions. The UI's saved time advances only after transaction completion. On restart, up to three sessions (including the current one once it starts) are retained, with at most 2 MiB per serialized report. Old records are replaced/pruned rather than appended indefinitely. Repeated boots without starting audio never create new checkpoints or overwrite the recovered fault session.
- Checkpoints remove duplicate nested phone snapshots, retaining the original build/capture time, device/context/timing/resource data, console events, timeline and marked incidents. Oversized reports explicitly shorten console text and older history before giving up; failed/quota-blocked writes leave the earlier checkpoint intact and show a warning. Runtime write failures retry at most once per minute while the engine exists, so transient storage problems can recover without a retry storm; Mark/Submit can also request a manual retry. No audio samples are stored in this diagnostic database, and the separate `GranularSynthAudioDB` is unchanged.
- Recovered sessions remain available for Copy/Download/Submit. Successful upload saves the receipt locally without deleting the capture; a receipt for an older version never marks newer unsent data as submitted. Uploads remain strictly manual, including after a restart or network failure.
- Recovery is limited to the last completed checkpoint: an abrupt process kill can lose the newest seconds, blocked/background JavaScript cannot maintain a five-second schedule, and a browser/OS may clear site storage. Private browsing or clearing site data can remove the logs. Do not clear site data when troubleshooting. This cannot recover logs lost before this build was installed.
- `node --test tests/audio-debug-storage.test.js` checks bounded retention, two simulated hours, repeated empty restarts, quota failures, corrupt data, concurrent writes/clear and receipt versioning. `node tests/audio-debug-recovery-browser.js` terminates the renderer without an unload handler, reopens the app, checks offline/reload/retry, submits the original capture without starting audio, and verifies Copy/Download and unrelated settings/audio storage. Uploads are mocked unless `MYGRAIN_ALLOW_LOG_UPLOAD=1` is explicitly set against the isolated server or an authorized synthetic public test.

### Submitted logs

- Submit Log makes one same-origin `POST /mygrain/api/debug-logs`, disables duplicate taps while pending and displays a server-assigned reference only after the server confirms the write. Failures leave the local capture available for Copy/Download; there are no background retries or engine changes.
- Copy/Download/Submit retain the full current phone timeline and marked incidents. The structured report's twenty recent audio snapshots omit redundant nested phone captures so a long session does not repeat the entire timeline twenty times; their gains, nodes and warnings remain intact.
- The existing `fs7300-documenter.service` loads `backend/mygrain_debug_logs.py`. JSON reports are written atomically as `/var/lib/mygrain/audio-debug-logs/<reference>.json`, outside every static root, with directory mode 0700 and file mode 0600. Server administrators can read them directly; no HTTP listing, read endpoint or public log link exists. The app is public: upload validation is an abuse guard, not user authentication or proof of report authenticity. Reports and console text should be treated as private, untrusted input.
- Uploads require the app origin and custom JSON header, with a 4 MiB request limit, ten-second body-read timeout and twenty accepted uploads per server minute. Storage stops accepting submissions at 1,000 reports, 256 MiB or less than 32 MiB free disk reserve. Existing reports are never automatically deleted; an administrator must archive/remove them when full. Backend changes require a service restart; no proxy change is needed.
- `python3 -m unittest discover -s tests -p test_debug_logs.py`, `node --test tests/debug-log-submit.test.js` and `node tests/debug-log-submit-browser.js` cover validation/private storage, actual HTTP routing, mobile taps, receipts, duplicate suppression, retries and playback continuity. The browser test mocks uploads by default. Set `MYGRAIN_TEST_URL` to the isolated `tests/song-beta-test-server.py` host and `MYGRAIN_ALLOW_LOG_UPLOAD=1` to exercise actual isolated storage; do not enable real public uploads unless explicitly testing a synthetic submission.

## Long-running audio resources

- Finished X notes detach their individual filter-modulation input from the shared LFO as well as disconnecting their output nodes. Other voices and the shared LFO phase remain intact; no periodic engine restart or browser refresh is used.
- Oscillator and hard-sync waveform caches each retain at most 128 entries, including when modulation continuously changes shape or sync ratio. Eviction does not change active voices. Unsynced native sine/triangle/sawtooth/square voices skip custom waveform calculations whose results were previously discarded.
- Modulated custom waveforms sample their 512 source points once and reuse one fixed Fourier basis, rather than resampling every point for each of 96 harmonics. Float32 coefficients remain identical. Held voices evaluate modulation at one shared audio-clock instant per update so identical waveforms reuse the cache.
- When L, X, drums, the sequencer or granular scheduling misses its lookahead window, it skips expired events and advances the pattern phase instead of replaying overdue notes/grains in a burst. Drum and sequencer scheduling use a fixed lookahead deadline per tick. This is recovery from a delayed callback, not an engine reset, and does not change levels, presets or Song-part data.
- Copy/Download Debug includes late scheduling ticks, skipped stale steps and worst lateness in milliseconds. Counters reset with a new audio context; a few startup misses alone do not identify a persistent audio problem.
- `node --test tests/audio-resource-lifecycle.test.js` checks repeated cleanup, overlapping voices, LFO replacement, bounded caches and native-wave configuration. `node tests/audio-resource-lifecycle-browser.js` runs three-minute X/A/drum playback checks at each of 44.1/48 kHz against the public host, blocking remote writes. `MYGRAIN_SOAK_SECONDS` controls the duration per rate. `node tests/oscillator-wave-cache-browser.js` compares rendered sound before/after cache eviction. Chromium phone emulation is not physical iPhone/Safari validation.
- `node --test tests/audio-deadline.test.js` checks stale-event recovery, fixed deadlines, exact Fourier coefficients and shared modulation timing. `node tests/audio-workload-browser.js` profiles four held, continuously modulated custom-wave voices under 4× CPU throttling and injects a ten-second X scheduling backlog. For a mixed long run, use `MYGRAIN_MODULATED_SYNTH=1 MYGRAIN_CPU_THROTTLE=4 MYGRAIN_SOAK_SECONDS=600 node tests/audio-resource-lifecycle-browser.js`; it adds synth and granular voices to the loop/drum test, recording callback gaps, cache sizes and scheduling counters. `MYGRAIN_SAMPLE_RATES=44100` or `48000` selects one rate.

## Drum reverb send

- Both drum Reverb Send buttons enable the shared reverb. If Room Mix is zero when you manually switch the send on, it starts at 30%; an existing positive mix is preserved. Silent preset/Song restoration retains the saved mix, including zero, and you can still turn Room Mix down manually.
- Drum Verb Send updates the live send gain immediately, from 0–200%. The send includes the separate SC-kick bypass route as well as normal/direct drum output, without changing dry drum levels. One-shot hits and their room tails keep the wet output awake after transport stops.

## Loading and randomisation defaults

- Dry Trim, Filter In and Filter Out start at 0.0 dB on startup/browser-state reload, preset loading, Reset Patch and ordinary/Mega/Sparse randomisation. Their actual audio controls and performance mirrors are reset together. Filter gain LFO routes are cleared and Auto Makeup starts off so the filter gains remain at unity; manual trim, modulation and Auto Makeup changes still work during a session. Exact Song-part restoration is unchanged.
- Startup (including restored browser settings), preset loading, Reset Patch, Mega and Sparse start with Ring Mod, all four bus drives, global distortion and snare distortion at 0%, Bus Comp at 30% and Comp Release at 100 ms. Global distortion LFO routes are also cleared so a zero amount stays clean. These are defaults, not locked controls: manual adjustments still work during the session.
- Song-part snapshot restoration remains exact rather than applying startup/preset defaults mid-song. Existing frozen audio is not rewritten.
- SC Kick Level is an independent trim, multiplied by the drum Kick level only when Sidechain Key is **SC Kick**. With **SC Off** or **SC LFO1**, it has no effect on the kick. The two sliders save independently; changing one no longer moves the other. Existing state and preset schemas are unchanged.

## X filter accent

- X's Filter Accent changes the filter envelope on accented steps, not their audio gain or exported MIDI velocity. Positive values add up to 50 percentage points of envelope; negative values subtract up to 50, clamped to 0–100%. Zero leaves the normal Filter Env unchanged.
- X's level and audition paths no longer apply the additional 0.88 attenuation. The shared mix headroom, mixer level, enable switch and solo routing remain active. Existing saved accent values and step flags load unchanged; no patch or song format migration is needed. Filter sweeps can still change perceived loudness by removing or passing frequencies.

## RADIOLAB original design (R.1 history, superseded by R.8 recording)

- Supported account-backed app: `https://openclaw.blackcarburning.com/mygrain/`. The older GitHub Pages copy does not provide these authenticated radio services.
- Build `v2026.10.17.R.1` adds an account-private Internet-radio recorder, not a loop generator. The existing K.20 account/login controls, Q asset marker, audio engine and Song formats are unchanged. Station choices come only from `GET /mygrain/api/radiolab/stations`; spoken/news/public/state radio and Russian, Chinese and Japanese sort first. There is no custom station URL field.
- Press **Listen / Tune** to create/resume Web Audio and start the selected same-origin relay. Native media uses the approved `/mygrain/radiolab/stream/<id>?_mygrain_user=<signed-in username>` URL; API requests use the existing account-aware fetch wrapper. No microphone, autoplay, global gain change or transport start is involved. **Monitor** changes only radio listening volume; its PCM tap remains active.
- A true stereo PCM AudioWorklet tap continuously maintains at most 15 seconds of received audio. The accessible spin wheel supports pointer/touch drag, scrolling, arrow keys, Page Up/Down and Home/End; a labelled range input is an alternative. Rewind clamps to actual warmup. Audition plays the selected past-to-live segment once, temporarily silencing only the live radio monitor. The live capture buffer continues advancing. Select zero for the live edge.
- **Record** freezes a copy of the selected pre-roll at the button press, then appends arriving live PCM exactly once until **Stop**. It never schedules beats, repeats, cuts, resamples, or automatically snapshots audio. Later wheel movement cannot alter a take. Station changes are blocked while recording. **Stop** pauses radio and preserves the ring/take; another Listen starts a fresh buffer. Completed takes survive station changes; another Record replaces the unsaved take. The recorder stops automatically only at the explicit safety limit: 120 seconds including pre-roll, or 32 MiB stereo Float32 recording PCM, whichever is first (about 87.4 seconds at 48 kHz). WAV output is ordinary stereo PCM16 at the context's actual sample rate. Recording chunks, the 15-second ring, and the final WAV are bounded; no decoded radio PCM is stored in localStorage or IndexedDB by RADIOLAB.
- **Save** posts the finite raw WAV to `/mygrain/api/radiolab/samples?name=...&station=...`. **Browser** lists only the signed-in account's `SAMPLES_RADIOLAB`, stored locally by the server, not in Dropbox. Its one-shot Play fetches `/mygrain/api/radiolab/file?name=<filename>` through authenticated fetch, then decodes in memory; `sample.url` is not trusted as a native media URL. Save failures retain the unsaved take for retry. No production data or captured station audio is written by the frontend tests.
- Browser **Load Selected** uses the established Main Grain / Grain A / Grain B or Loop V loaders, loading the complete saved file without starting playback. Grain folder choices include `samples_radiolab`. Loop V visibly exposes **Use RADIOLAB** and its private full-file folder; that button opens the same chooser with Loop V selected. Loading into V disables a previous vocal cut and preserves the full duration; subsequent destination instrument playback remains the existing Loop V behavior, not a new radio transport. RADIOLAB's live ring/take is never included automatically in Song/patch exports. Only explicitly loading a saved sample into an instrument participates in that instrument's existing account-scoped persistence.
- Account lock or `pagehide` aborts radio requests, disconnects only radio nodes, removes native stream URLs, stops previews and clears private ring/recording/list state. An owned AudioContext is closed; a shared engine AudioContext is never closed, suspended or muted by RADIOLAB. Back/forward restoration requires another listening gesture. ScriptProcessor is an explicitly labelled fallback if AudioWorklet cannot load; queue overflow/processor failure stops capture with a visible status instead of silently splicing missing blocks. Live Russian/Chinese MP3 and Japanese AAC playback is verified through the public relay in Chromium. Physical Safari/iOS and background/lock-screen behavior remain untested.
